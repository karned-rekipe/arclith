# Release 0.31.0

## Contexte et décision

La PR #241 livre #223, deuxième phase de l'epic #221 : un blueprint
`state-machine` paramétré par une spec métier, avec cycle de vie typé, erreurs
contextualisées, persistance compare-and-swap et rejeu portable.

- publier `arclith` en `0.31.0` et `arclith-cli` en `0.28.0` ;
- imposer `arclith>=0.31.0` à la CLI afin qu'un projet généré utilise la version
  coordonnée du framework ;
- conserver les manifests V1 et les digests historiques des blueprints non
  paramétrés ;
- utiliser le tag signé commun `v0.31.0` et les deux Trusted Publishers
  existants ;
- ne modifier ni les protections GitHub ni les credentials PyPI.

## Périmètre

Cette release publie la spec V1, le manifeste paramétré V2, la génération et le
rejeu du cycle de vie. Elle ne transforme pas la machine en moteur dynamique,
n'ajoute aucun transport et ne fournit pas d'adapter de persistance de
production implicite. #221 reste ouvert pour les phases suivantes de la
roadmap ; #223 est Done après fusion de #241.

## Validation prévue

Precommit, complexité, couverture, suite CLI complète, MkDocs strict,
construction et inspection des wheels/sdists, PR de release et review
thread-aware. Après fusion et tag signé : vérifier les deux publications
publiques PyPI puis installer sans cache un service `Invoice` neuf, exécuter ses
tests générés et contrôler le refus des mutations génériques, une transition
autorisée et un conflit de version. Aucun déploiement de microservice n'est
inclus.
