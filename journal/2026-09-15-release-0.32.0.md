# Release 0.32.0 — clôture de l'EPIC #221

## Décision

L'utilisateur autorise la publication des paquets et la clôture du suivi GitHub.
Le dépôt est synchronisé sur `bc9283e`, après les PR #243 (Job), #244
(Synchronization), #229 (CI) et #245 (Workflow). Le répertoire utilisateur
`catalog-servicea/` est préservé.

- Arclith : 0.31.0 → 0.32.0.
- CLI : 0.28.0 → 0.29.0, avec minimum `arclith>=0.32.0`.
- Versions, fallback du scaffold, assertions associées et locks alignés.
- Guides des trois blueprints : installation publique et environnement propre
  au projet généré ; README CLI, changelog et procédure de release mis à jour.
- Formats de manifeste/recette et digests des blueprints inchangés.

## Livraison

La release passe par une PR dédiée, les contrôles de qualité et la relecture
des conversations GitHub, puis un tag signé et les deux Trusted Publishers
existants. La clôture de #221 intervient après vérification des distributions
publiques, de la documentation Pages et d'un consommateur neuf sans source locale.
Les cinq issues enfants sont déjà fermées ; #226 est passée de In review à Done.

## Validation locale

- `make quality` : 2 831 tests passés, 5 ignorés, couverture 92,28 % ; lint,
  types, sécurité et complexité validés.
- Suite CLI complète : 859 tests passés, avec un avertissement de dépréciation
  Pydantic préexistant dans un test CRUD.
- MkDocs strict et vérification des deux locks réussis.
- Wheels et sdists des deux distributions construits ; métadonnées Python 3.13
  et minimum `arclith>=0.32.0` inspectés ; quatre archives validées par Twine.
- Environnement Python 3.13 neuf avec les wheels non éditables : six blueprints
  découvrables, six projets compilés, 39 tests générés passés.
- Scénarios consommateurs validés : Job avec vingt soumissions idempotentes,
  conflit de payload et modèle personnalisé préservé ; Synchronization avec
  échec partiel/retry incrémental et désactivation full ; Workflow avec checkpoint
  incertain, clé stable, absence de double effet et annulation.
- Deux tests de compatibilité incluaient dans leurs empreintes le numéro du
  framework installé. Ils fixent désormais explicitement la version historique
  0.31.0 pendant le replay, sans modifier les fixtures ni les digests.

## Limites

La V1 publie le catalogue de six blueprints, incluant CRUD. Les stores mémoire
ne deviennent pas durables : les adaptateurs persistants, DAG, sagas, moteurs
externes et projections de transport restent hors du périmètre de #221.
