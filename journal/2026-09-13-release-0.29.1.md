# Release 0.29.1

## Contexte

La PR #237 corrige la génération CRUD de `arclith-cli` pour projeter les vrais
champs métier d'une entité, leurs contraintes Pydantic et leurs dépendances dans
les contrats de création, de mise à jour et dans la projection FastAPI.

Cette itération porte principalement sur la CLI. Le workflow du dépôt publie les
deux distributions depuis un tag commun ; la version du framework et la
dépendance minimale générée restent donc synchronisées avec la CLI.

## Décision

- publier `arclith` en `0.29.1` ;
- publier `arclith-cli` en `0.26.1` ;
- relever la dépendance minimale de la CLI à `arclith>=0.29.1` ;
- utiliser le tag commun signé `v0.29.1`, qui déclenche les deux Trusted
  Publishers PyPI.

## Impact

- génération : les commandes CRUD reprennent les champs métier, types, valeurs
  par défaut et contraintes Pydantic inspectables ;
- FastAPI : le `POST` conserve les champs requis et le `PATCH` reste partiel en
  distinguant omission et valeur invalide ;
- robustesse : aliases, annotations différées, constantes de classe, imports et
  rebindings sont analysés statiquement avec un comportement fail-closed ;
- compatibilité : les fichiers de transport générés restent developer-owned et
  les adapters demeurent explicitement sélectionnés ;
- déploiement : aucun déploiement applicatif, publication des deux distributions
  PyPI uniquement.

## Validation prévue

- suites complètes framework et CLI, couverture minimale à 90 %, Ruff, mypy,
  Bandit, Radon et MkDocs strict ;
- construction et inspection des wheels et sdists des deux distributions ;
- PR de release, audit des conversations de revue, merge et tag signé
  `v0.29.1` ;
- suivi des deux jobs Trusted Publisher, vérification PyPI puis installation
  sans cache dans un environnement consommateur isolé ;
- génération d'un nouveau service FastAPI et parcours HTTP réel des cinq routes
  CRUD.
