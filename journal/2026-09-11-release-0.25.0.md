# Release 0.25.0

## Contexte

Depuis `v0.24.0`, la PR #216 rend le scaffold CLI réellement incrémental :

- `init` ne génère plus FastAPI, FastMCP ou leur dépendance avant leur sélection explicite ;
- `add-adapter` expose toutes les capabilities, y compris `api/fastapi` et `mcp/fastmcp` ;
- les repositories et les transports générés correspondent uniquement aux choix utilisateur ;
- le point d'entrée API utilise une factory Uvicorn importable pour préserver l'auto-reload sans
  importer FastAPI dans un projet minimal.

## Décision

- publier `arclith` en `0.25.0` ;
- publier `arclith-cli` en `0.22.0` ;
- relever la dépendance minimale de la CLI à `arclith>=0.25.0` ;
- conserver le tag commun `v0.25.0`, qui déclenche les deux jobs Trusted Publisher existants.

La publication conjointe est nécessaire : le `main.py` généré par `arclith-cli 0.22.0` appelle le
nouveau paramètre public `Arclith.run_api(..., factory=True)`. Autoriser `arclith 0.24.0` créerait
donc un couple de versions installable mais incompatible à l'exécution.

## Impact

- framework : ajout rétrocompatible du paramètre keyword-only `factory` à `Arclith.run_api` ;
- CLI : parcours interactif complet et génération strictement à la demande ;
- dépendances : FastAPI et FastMCP deviennent réellement optionnels dans les projets initialisés ;
- données et déploiement : aucune migration et aucun déploiement applicatif, publication PyPI
  uniquement.

## Validation prévue

- `make precommit`, `make coverage` et build strict de la documentation ;
- suite complète `arclith-cli`, lint CLI et contrôle des lockfiles ;
- construction et validation des wheels et sdists des deux distributions ;
- PR de release, tag signé `v0.25.0`, puis suivi des jobs Trusted Publisher ;
- vérification des versions PyPI et smoke test sans cache dans un environnement isolé.
